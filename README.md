# 课程 AI 助教原型 · Dify + DeepSeek

> 用 Dify 搭建的课程问答原型，展示**知识库检索增强问答（RAG）**从搭建、测试到提示词迭代的完整过程。
> 应用类型：**Chatflow**（预设流程的检索增强问答），非自主规划/动态选工具的 Agent。

## 做了什么

参照课程平台「AI 助教」的功能配置思路，用 Dify 实现「课程资料问答」：

- 把课程资料接入知识库，做高质量索引 + 向量检索；
- 编排一条 Chatflow：**用户输入 → 知识检索 → LLM → 直接回复**；
- 检索结果绑定到 LLM 上下文，SYSTEM 提示词引用 `{{#context#}}`；
- 开启**来源引用**，回答下方显示资料出处。

## 流程与节点

```
用户输入 ──> 知识检索 ──> LLM ──> 直接回复
 (start)   (knowledge-  (llm)    (answer)
           retrieval)
```

| 节点 | 配置要点 |
|---|---|
| 知识检索 | 向量检索，`qwen3-rerank` 重排，Top K = 4；检索输入为学生提问 `sys.query` |
| LLM | 对话模型 `deepseek-r1`；上下文绑定知识检索结果 |
| 直接回复 | 输出 `llm.text` |

## 知识库资料

由于现有课程只有知识点名称、没有配套讲义，本原型使用 **5 条模拟课程问答**（学习顺序 / 作业提交 / 答疑安排 / 课前准备 / 自测未通过），覆盖典型课程问题。**时间、地点及要求均为虚构**，仅供功能演示，不代表任何真实课程规定，也不提供专业实验操作依据。

资料见 [`食品理化检验-模拟课程问答.txt`](./食品理化检验-模拟课程问答.txt)。

## 提示词迭代（一次实际改进）

发现「资料没写上限」容易被模型表述成「没有限制」，于是给 SYSTEM 提示词增加一条规则：

> 严格区分"资料未说明"和"明确没有限制"。资料未提及某项规定时，应回答"资料未说明，暂时无法确认"，不得推断为无限次数、没有要求或默认允许。

用同一问题复测，模型从「不设限」的暗示改为「未说明重做次数上限」，符合预期。

## 测试记录（人工检查）

| 问题 | 结论 |
|---|---|
| 老师每周什么时候答疑，在哪里？ | 通过（答出时间地点 + 模拟说明 + 文件引用） |
| 换一种问法问答疑 | 通过（答案一致，保留模拟说明与引用） |
| 作业最晚什么时候交？文件要求？ | 通过（核心事实正确） |
| 自测多少分及格？能重做几次？ | 初测措辞易误读 → 提示词调整 → 复测通过 |

这些是少量演示用例的人工检查，不代表整体准确率，也不证明所有资料外问题都能正确处理。

## 边界（诚实声明）

- 这是**演示原型**，尚未在真实课程中使用；
- 未做多轮追问、无人监督评估、真实学生使用、成本效率收益的验证；
- 知识库引用与凭据已脱敏（`dataset_ids` 替换为 `REDACTED`），模型供应商需自行配置。
